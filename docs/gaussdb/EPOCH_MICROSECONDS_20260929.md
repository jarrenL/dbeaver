# Epoch 微秒转换与非法输入回归

## 对应范围

历史清单的日期时间转换、结果值显示和编辑验证。测试直接调用 DBeaver 的 EpochTimeAttributeTransformer 生产转换器；不是 GaussDB JDBC TIMESTAMP 类型测试，也不是结果集界面操作验收。

## 场景与复现

新增10项，原有3项保留：

- 微秒数值0、1、42、999999、1000001、-1、-1000001，以及2024年闰日的带六位小数时间。分别检查显示文本和文本反向转换后的精确整数。
- 无效日期文本、合法文本后带多余字符：必须抛出DBCException并保留DateTimeException原因，不得将异常对象当成单元格值返回。同一转换器随后仍可解析合法输入。
- 原有秒（巴黎时区）、毫秒和纳秒（UTC）往返继续回归。

修复前13项中9项失败：微秒余数未换算成纳秒，格式使用纳秒数字字段而非六位秒小数，导致值损失或负数显示九位小数；非法输入返回异常对象而不抛出。红测日志：`/tmp/epoch-micros-red-20260929.log`。

## 实现与结果

微秒余数乘1000后传入Instant，格式改为`SSSSSS`；解析失败抛出带原始原因的DBCException，新增中英文资源文本。其他单位的转换算法没有修改。

修复后专项 **13/13通过，零跳过**。共享模型层变更执行了73模块、五个测试模块的诊断回归：**2568项，2394通过，173跳过，0失败，1错误**。唯一错误为RestTest本地网络操作被拒绝。诊断运行允许后续模块继续执行，但独立验收门禁拒绝整体通过，不能以Maven的SUCCESS代替验收。

完整逐项结果见[测试证据](evidence/EPOCH_MICROSECONDS_REACTOR_20260929.json)，绿测日志：`/tmp/epoch-micros-green-20260929.log`。
