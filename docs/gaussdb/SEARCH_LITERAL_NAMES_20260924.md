# 对象搜索特殊名称验证

## 对应范围

历史清单 1.4 标识符转义、3.4 特殊字符名称和 9.5 对象搜索。调用生产 PostgreStructureAssistant 搜索逻辑，通过 JDBC 接口桥接真实 GaussDB 507 目录；两种部署独立验证。此报告不替代搜索窗口的键盘操作验收。

## 输入与断言

在随机隔离 schema 创建六张表：

```text
literal%percent
literal_percent
literalXpercent
literal\path
研发'表
quote"name
```

CREATE 使用带双引号的标识符，并将内嵌双引号加倍；搜索使用参数绑定的 LIKE 模式。

- 按每个完整名称生成转义模式（先转义反斜杠，再转义 % 和 _），生产搜索结果必须且只能是原名称。
- 不转义 `literal_percent` 时，单字符通配符应匹配前三个名称，作为正向对照，避免只验证“始终精确匹配”。
- 带 SQL 注入形状的搜索字符串只应得到空结果；随后通配搜索仍返回六张表，不应执行字符串中的 DROP。
- finally 清理隔离 schema。

该场景验证已有搜索模式语义，不改变 %/_ 的通配行为。中文、单引号、双引号及反斜杠都作为对象名数据处理。

## 结果与限制

`run-kenIYD` 集中式、分布式两个新增测试均通过。整套新鲜结果为 1411 项、1387 通过、24 跳过、0 失败/错误；临时授权角色已删除。[脱敏逐例结果](test-results-20260924-search-literal.json)。

本轮未修改生产代码，不代表搜索 GUI、所有名称长度/Unicode 规范化或跨数据库搜索均已验收。
