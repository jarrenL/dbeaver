# 凭据保存失败传播与重试

## 问题

`DataSourceSerializerModern.saveSecureCredentialsFile` 捕获全部异常并仅记录日志，导致实际凭据文件写入或清理失败后，公开 `saveDataSources` 仍正常返回。上层注册表据此可能清空保存错误状态，形成部分保存却未报告失败的风险。

新增四项故障注入：写入非空加密凭据/清理空凭据 × `IOException`/`DBException`。首次运行四项均失败，原因都是预期异常未抛出，见 `/tmp/credential-write-failure-red-20260929.log`。

## 修复与验证范围

移除吞异常逻辑，声明并向上层传播原始异常。检查该方法仅有公开保存入口这一处生产调用，公开入口已声明这两种异常，上层注册表已有记录错误的路径。

四项测试使用真实保存器和加密器，配置管理器在指定凭据文件的第一次写入时抛错。断言：

- 保存入口抛出相同异常对象，不把失败改成成功；原内存密码保持。
- 主配置文件此时已写出，凭据文件未被模拟存储接受；**不宣称两个文件原子提交或自动回滚**。
- 同一保存器显式重试成功；检查凭据清理请求或解密后的完整用户凭据输出，确认两次凭据写入调用。

修复后 `ConfigurationReadFailureTest` **57/57 通过、零跳过**。配置管理器是故障替身，不是实际磁盘满、权限变化或断电测试，也未验证 GUI 错误提示。

复验日志：`/tmp/credential-write-failure-green-20260929.log`。

完整 73 模块诊断 2,516 项：2,346 通过、169 跳过、1 项 Rest 本地网络权限错误。独立逐项门控仍拒绝通过；诊断的继续执行参数不代表忽略验收失败。逐项证据：[CREDENTIAL_WRITE_FAILURE_REACTOR_20260929.json](evidence/CREDENTIAL_WRITE_FAILURE_REACTOR_20260929.json)。不与之前批次计数相加。
