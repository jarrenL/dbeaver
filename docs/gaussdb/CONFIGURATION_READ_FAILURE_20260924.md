# 配置读取故障与异常保留

## 适用场景

历史清单 3.12、10.3、10.4 中配置读取和异常处理。测试通过反射调用生产 `DataSourceSerializerModern.readConfiguration`，使用模拟配置管理器、可控输入流以及真实加密器。未访问用户连接文件或实际密码。

## 十项测试

| 场景 | 数量 | 验证 |
| --- | ---: | --- |
| 正常读取 | 2 | 明文/加密 JSON 中中文和扩展汉字保持一致，输入流关闭 |
| 有效内容后读取失败 | 2 | 即使已读数据能够解析，随后发生 IOException 也必须报错；保留原始原因，关闭流，不进入解密 |
| 立即读取失败 | 2 | 不误认为缺少配置，保留原始 IOException，不进入解密，关闭流 |
| 关闭流失败 | 2 | 明文/加密读取不报告成功，保留关闭失败原因 |
| 文件不存在 | 1 | 正常返回 null，不调用解密器，与读取失败区分 |
| 读取与关闭同时失败 | 1 | 原始读取异常为主因，关闭异常保留为 suppressed，流只关闭一次 |

## 缺陷与修复

`run-JcPvwx` 复现四项失败：`loadConfigFile` 捕获复制输入流的异常后，仅记录日志，仍使用缓冲区内容继续处理。读到有效 JSON 或完整密文后再出现 I/O 异常也可能被接受；立即读取失败的原始原因也会丢失。

首次修复后 `run-zJbNz5` 两项关闭故障测试揭示复制工具自身也会关闭输入流；与外层重复关闭叠加后可能掩盖原始异常。最终改用不关闭输入流的 `InputStream.transferTo`，传播读取 IOException，交由拥有输入流的调用方关闭并包装异常。不修改有效配置内容、加密格式和文件不存在时的语义。

## 边界

本轮覆盖底层配置读取，不等于整个项目加载已验收。上层 `parseDataSources` 仍有捕获 DBException 后继续处理的分支；项目 UI 提示、旧连接保留、后续保存行为、文件原子替换及权限需另验。输入流故障为可控模拟，不是磁盘硬件故障或桌面云断网实测。

## 结果

`run-c2ik2b` 新增十项全部通过；整套新鲜结果 1463 项、1439 通过、24 跳过、零失败/错误，包含已启用的两种部署真库用例。跳过不算通过，格式检查在本次命令中跳过。临时授权角色已删除。[脱敏逐例报告](test-results-20260924-configuration-read-failure.json)。
