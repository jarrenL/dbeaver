# 查询历史删除：浏览接口与界面接入

对应历史清单 3.11：删除历史项、清理已删除项、异步更新。

## 行为

- 查询管理器删除所选行时，先请求历史服务删除对应事件对象，成功后移除界面行。
- 清空按钮只删除当前显示的记录，不删除被过滤或尚未加载的历史记录。
- 刷新只清理界面并重新读取历史，不能触发删除。
- 旧历史服务未实现删除接口时明确报错，保留界面记录，不伪装成功。
- 已删除事件不因延迟到达的界面更新重新加入；其他视图在后续更新时清除已删除对象。
- 不执行数据库 DELETE，不修改已经写出的 SQL 日志文件。

## 自动化验证

`QueryHistoryCursorTest` 新增浏览接口精确传递所选对象，以及不支持删除时拒绝操作两项测试。此前 `QueryHistoryCollectorTest` 已覆盖 BEGIN/END 共用对象、重复删除、派发前删除及后续重复事件不复活。

最终构建结果见 `test-results-history-delete-browser-20260924.json`；跳过项不计为通过。

## 尚需验收

本次源码接入不等于已经完成新版本 GUI 验收。需在安装新插件后重测：删除后刷新、清空后刷新、过滤后清空保留其他记录、刷新本身不删除，以及新查询继续进入历史。旧版本 GUI 已复现的记录复活问题见 `QUERY_HISTORY_GUI_20260924.md`。

跨重启历史恢复是独立能力，本次修改不实现磁盘历史加载。

## Linux GUI 补验

在麒麟 V10 x86_64 隔离客户端正常退出后安装 model `2.0.45.202609232228`、SQL 编辑器 `1.0.185.202609232228`，随后正常重启。不是全量产品包验收。

1. 在真实 GaussDB 507 分布式连接执行两条 SELECT，分别返回 `history_delete_gui_20260924_keep`、`history_delete_gui_20260924_drop`，均成功且返回一行。
2. 打开查询管理器并刷新，两条记录均存在（队列快照 881）。
3. 搜索 drop 标记，待异步读取结束后只显示一条记录（884）。
4. 点击“清除日志”，当前列表为空（885）；点击“刷新查询历史”后仍为空（887）。
5. 清空搜索文本，keep 记录仍存在，drop 记录没有恢复（889）。

独立测试仓 `scripts/verify-history-filtered-clear.mjs` 检查四份实际控件快照并通过。将“清空后刷新”快照替换为删除前的记录作为负对照，校验明确失败。因此本轮证明过滤清空不复活且保留隐藏记录，不证明单选右键删除、跨重启恢复或其他历史服务实现。
