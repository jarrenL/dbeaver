# 对象过滤匹配与缓存验证

对应清单 3.12 的 schema 包含/排除规则及 9.5 的名称大小写边界。直接调用生产 `DBSObjectFilter.matches/matchesAny`；不依赖 mock 匹配结果，不修改数据库对象。

## 场景

| 场景 | 输入与预期 |
| --- | --- |
| 精确包含（2 项） | 分别开启/关闭大小写敏感；Bank.+ 必须按字面量匹配而非正则，中文表匹配，bank.+ 是否命中随规则变化；matchesAny 同样生效。 |
| 精确排除（2 项） | 包含 %，排除 Bank；大小写敏感时 bank 保留、不敏感时排除；替代名称中任一命中排除即拒绝。 |
| 包含缓存切换 | Bank% 先缓存不敏感匹配，改敏感后拒绝 banking、接受 Banking，再改回恢复匹配。 |
| 排除缓存切换 | Bank% 排除规则同样在两次切换后及时生效。 |
| 列表替换 | 缓存包含/排除后换成 Other% 并清空排除，新规则立即生效、旧结果不残留。 |
| 副本隔离 | 已缓存敏感过滤器复制后，副本改不敏感、增加掩码，原对象的规则与结果不变。 |

## 发现及修复

`run-iKMA0d` 新增 8 项中 4 项失败：精确名称始终 equalsIgnoreCase；更改大小写设置没有使已编译的包含/排除模式失效。修复为敏感精确值使用 Pattern.quote 字面量模式；setCaseSensitive 在值变化时清空两类缓存，并与 matches 使用相同对象锁。

生产 `DBNDatabaseNode` 会按数据源方言的 hasCaseSensitiveFiltration 设置规则。此处验证的是该规则的模型行为，不宣称界面已有独立大小写开关，也不更改任何方言的大小写能力定义。不敏感精确值保持原匹配规则，通配符语法保持不变。

## 边界

导航树实际刷新、各数据库方言以及 GUI 操作需另验；本轮不算真实树过滤端到端。该组件为共享模型，改动不限于 GaussDB。发布客户端尚未同步本轮 model 修复。
