# CLOB 临时文件分支回归

日期：2026-09-28。历史场景 1.6 资源/异常/取消、11.1 CLOB 类型。

正式 JDBCContentCLOBReadTest 新增五项：正常、读取失败、关闭失败、读/关同时失败、复制中取消。将内存阈值配置为 0，平台临时目录指向 JUnit 专用目录；使用生产 JDBCContentCLOB 与真实文件、UTF-8 Writer，Clob/Reader/监视器为测试替身。覆盖含中文扩展汉字的重复文本，Reader 每次返回 7 个 UTF-16 单元，验证完整文件和字节长度。

## 缺陷与修复

红测五项全部失败：大内容分支未关闭 Reader；复制工具在取消时正常返回，调用者仍将部分文件发布为缓存并释放原 CLOB。

修复将 Reader 与 Writer 一起纳入自动关闭；复制返回后检查取消并抛 InterruptedIOException，复用原有失败临时文件清理路径。关闭失败不发布缓存；读/关双重失败保留 suppressed。成功时再生成存储并释放原 CLOB。

测试明确验证失败后的专用目录为空、不 free 原 CLOB；同一对象解除故障后重试得到完整文本；正常缓存释放后对应临时文件删除。只操作 JUnit 专用临时文件，不涉及用户数据。

这证明文件分支的组件行为，不等于超大内存压力、真实磁盘故障、厂商 JDBC 故障、GUI 取消提示或数据库回滚。测试固定 UTF-8，不覆盖数据源编码偏好解析。底层阻塞 I/O 不保证立即中断，完整安装包和真库端到端仍待验证。
