# 日期偏移解析验证

## 生产缺陷

`DateTimeDataFormatter` 自动返回类型原来根据格式字符串是否包含大写 Z 决定。ISO 偏移格式 X/XXX 可以解析偏移，但自动路径返回 LocalDateTime，偏移被丢弃；引号内的字面 Z 则被误判为时区，返回旧 Date 类型。

修复改为解析后依次提取 OffsetDateTime、LocalDateTime，而不是搜索格式字母。显式类型提示路径不变；仅日期/时间的旧返回类型仍保留此前严格校验。

## 测试

本轮增加六项：

- X/Z、XX/+0800、XXX/+08:00、Z/+0800 四组格式，时间包含 .001234 微秒值。验证显式 OffsetDateTime 与自动类型返回同一个带偏移值，格式化后恢复原文本。
- 引号内 'Z' 是普通文本，自动解析返回 LocalDateTime，不附加伪造偏移。
- 小写 xxx 当前在旧格式器初始化时被拒绝。此项仅记录能力边界，**不代表支持小写 x**。本轮不扩大自定义格式语言。

首次 `run-wzdX5W` 使用 XXX、xxx、X、Z 与字面 Z：3 项断言失败、xxx 初始化错误、Z 正常。随后将正向矩阵的 xxx 改为受支持的 XX，并独立保留 xxx 限制测试；没有将初始化错误伪装成正向功能通过。失败运行不用于汇总其他模块的新鲜结果。

## 边界

修复后 `run-aIRTsG` 六项新增测试全部达到各自预期；整套新鲜结果 1407 项、1383 通过、24 跳过、0 失败/错误。临时授权角色已删除。[脱敏逐例报告](test-results-20260924-date-offset.json)。其中一项是“不支持 xxx”的负向断言，不是新增支持能力。

本轮为共享生产组件验证，不替代 GUI 的编辑、错误展示和写回验收。地区时区名、夏令时歧义本地输入、客户全部自定义格式仍需另测。小写 xxx 的不支持状态仍然存在。
