# 非整点时区与夏令时边界验证

## 对应需求

历史场景清单 6.3 时间转换、11.1 日期类型，以及金融标准日期时间显示场景。验证客户端格式化与解析，不代替数据库 TIMESTAMP 类型读写或图形界面验收。

## 测试方法

正式平台测试 `DateTimeDataFormatterLocaleTest.fractionalHourZonesPreserveInstantAcrossCalendarAndDstBoundaries` 新增 8 个参数场景。使用生产 `DateTimeDataFormatter`，指定九位小数和带冒号的偏移格式。期望显示字符串为独立写定值，不使用被测格式化器生成。

每个场景检查 JDBC Timestamp、UTC OffsetDateTime、上海 ZonedDateTime 三种输入的输出一致；按自动类型和显式 OffsetDateTime 解析后均保持原始瞬间及纳秒，再格式化得到原文本。

| 场景 | UTC 输入日期时间（均附带 .123456789 秒） | 预期当地时间与偏移 |
|---|---|---|
| Lord Howe 回拨前的重复时刻 | 2024-04-06 14:45:00 | 2024-04-07 01:45:00 +11:00 |
| Lord Howe 回拨后的重复时刻 | 2024-04-06 15:15:00 | 2024-04-07 01:45:00 +10:30 |
| Lord Howe 前拨前一秒 | 2024-10-05 15:29:59 | 2024-10-06 01:59:59 +10:30 |
| Lord Howe 前拨开始 | 2024-10-05 15:30:00 | 2024-10-06 02:30:00 +11:00 |
| Kathmandu 跨闰日 | 2024-02-29 20:00:00 | 2024-03-01 01:45:00 +05:45 |
| Chatham 跨闰日 | 2024-02-29 12:00:00 | 2024-03-01 01:45:00 +13:45 |
| 固定负半小时时差回到闰日 | 2024-03-01 02:00:00 | 2024-02-29 22:30:00 -03:30 |
| 固定正四十五分钟时差跨年 | 2024-12-31 20:00:00 | 2025-01-01 01:45:00 +05:45 |
