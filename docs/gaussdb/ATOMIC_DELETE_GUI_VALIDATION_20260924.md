# GaussDB 批量删除原子性：麒麟图形客户端验证

环境：麒麟 V10 x86_64 隔离图形客户端，GaussDB 507 分布式测试库。客户端安装模型插件 `2.0.45.202609232338`、导航插件 `1.0.185.202609232338`，源码提交 `d7fd63a0cd`。这是指定插件更新后的客户端验证，不表示所有平台安装包已重新发布。

## 夹具与步骤

在确认不存在同名 schema 后，创建专用 `dbv_gui_batch_20260924`，三张表分别为 `batch_first(11)`、`batch_second(22)`、`batch_keep(33)`，归测试账号所有。创建只依赖第二张表的视图 `dependency`。

1. 打开连接导航树，展开数据库→模式，刷新模式列表，再展开测试模式→表。
2. 多选 first 和 second，右键“删除”；确认框列出这两张表，不勾选级联删除，点击“是”。
3. 等待整体错误对话框，核对 SQLSTATE 为 `2BP01`，指向第二张表及依赖视图；使用另一条 gsql 连接读取三张表。
4. 关闭错误框，只删除测试依赖视图；重新选择相同两表，从同一右键入口确认删除。
5. 通过独立 gsql 查询系统目录及未选表数据，并检查导航树刷新后的对象列表。

## 结果

| 场景 | 实际结果 | 结论 |
| --- | --- | --- |
| 第二对象存在依赖 | 整体错误对话框显示2BP01；first=11、second=22、keep=33全部保留，无逐对象跳过/重试窗口 | 通过 |
| 修正依赖后重新操作 | 独立目录查询仅剩batch_keep，数据为33；导航树仅剩同一张表，两张目标表均不存在 | 通过 |

SWTBot记录：931–940展开/刷新，941确认目标，942执行，943读取整体错误，944关闭，945重新确认，946执行，947检查完成状态。所有“通过”同时依赖数据库断言，不仅依据工具返回OK。修复前同一依赖场景会导致第一张表已删除，详见 `BATCH_DELETE_GUI_20260924.md`。

## 范围边界

结束后显式删除仅剩的测试对照表及专用schema，独立查询确认schema数量为0；没有删除业务对象。

仅确认同一实例、相同选项、无编辑器托管的两表批量删除。包批量删除、混合对象、UI中取消正在执行的事务、已有编辑器事务保留、连接中断及提交结果不确定仍需分别验证；模型层模拟取消测试不能替代UI取消场景。跨实例或编辑器托管选择仍按旧路径处理，不承诺整批原子性。
