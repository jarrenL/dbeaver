# 查询历史持久化：存储层验证

对应历史清单 3.11 持久化、删除、内容读取和异常处理。本阶段增加 `QueryHistoryStore`；尚未接入 `QMRegistryImpl` 或历史 UI，不能宣称产品已支持跨重启历史恢复。

## 实现范围

- 版本化 UTF-8 JSON 快照，显式字段保存 SQL、查询身份、项目/数据源标识、用途、模式/库名、时间、行数和错误信息。不序列化 JDBC 连接对象、连接 URL、密码或完整连接配置。
- UUID 去重更新，按执行开始时间保留最新记录，容量由调用方指定；文件最大 16 MiB。重开时也限制内存条目数量。
- 删除指定身份与按时间清理后先成功落盘，才更新内存；保存失败不假装删除成功。
- 同目录临时文件、文件内容 force、原子替换；不支持原子替换时返回错误，不降级为截断原文件。
- POSIX 临时文件权限为 0600，替换后的快照保持该权限；拒绝目标文件为符号链接或目录。调用方提供已存在、可信且由工作区所有者控制的目录。
- 损坏、未知版本或重复身份的快照读取失败，不静默覆盖原文件。异常不附带可能包含 SQL 内容的 JSON 解析错误。

## 自动化场景

真实临时文件测试，不模拟文件系统：

1. 中文、多行、引号与制表符重开读取，身份及原文不变，返回集合不可修改。
2. 删除、重复/不存在身份删除，重开后记录不复活，未选项保留。
3. 乱序写入、身份去重、容量淘汰和重开降低容量。
4. 保留期边界，恰好等于边界的记录保留。
5. 损坏 JSON、空/不完整快照、未知版本和 null 条目拒绝读取，原文件不变。
6. 保存目标变为目录，内存保持旧记录且目标目录不被覆盖。
7. 符号链接不跟随，外部目标内容不变（POSIX）。
8. 0600 权限和保存后无遗留临时文件（POSIX）。
9. 成功/失败记录、不同项目及连接身份、中文多行错误重开恢复。
10. 超出文件上限的更新失败，内存与磁盘原快照均保留。

首批八项在 run-8Hgu5M 通过，完整回归 1640 项/1617 通过/23 跳过/0 失败错误。后两项及重开降低容量补验在 run-FIyaOn 通过：完整回归 1642 项/1619 通过/23 跳过/0 失败错误；本类十项均通过，POSIX 两项未跳过。安全结果清单为 test-results-history-snapshot-store-20260924.json。

## 待接入及限制

必须在接入时落实记录开关与敏感命令过滤：SQL 正文本身也可能含敏感值，“不存密码字段”并不等于 SQL 无敏感信息。还需完成事件重建、当前/历史会话隔离、异步写入与关闭刷盘、删除同步、保留期调度以及 GUI 重启验收。

单实例拥有一个工作区文件，不支持多进程共享文件写入；Windows ACL、断电时目录元数据持久性、原子移动不支持的实际文件系统和进程被强杀时序尚未实测。文件内容 force 与原子替换不作为全平台断电不丢数据的保证。
