# 原子保存：提交确认丢失与清理异常

## 风险与修复

COMMIT调用抛错不能证明数据库没有提交。随后ROLLBACK成功也不能撤销已经提交的事务，因此不能自动重放同一批命令。原子保存路径现在在提交阶段失败、回滚失败或自动提交状态恢复失败后将命令上下文标记为不安全，拒绝再次保存，包括试图改用旧保存选项的重试。中文和英文诊断要求关闭上下文、刷新对象后重新确认操作。该标记属于当前命令上下文，不是数据库级分布式幂等标记；导航调用方仍负责关闭其隔离连接。

确认提交成功后仍先清除待执行命令并更新模型，避免清理错误使已提交命令重放。语句错误后恢复自动提交又失败时，保留语句错误为主异常，将恢复错误加入suppressed，不再掩盖原始诊断。

## 新增场景

| 场景 | 断言 |
| --- | --- |
| 提交调用抛错，回滚返回成功 | 原子保存及旧选项重试均拒绝；提交和命令执行不增加；不发布未经确认的模型更新 |
| 语句错误后恢复自动提交失败 | 返回原语句异常，附带恢复错误；重复保存不执行SQL |
| 已确认提交后恢复自动提交失败 | 待保存队列为空，模型已更新；不重复提交 |
| 真库提交后模拟响应丢失 | 生产saveChanges调用真实GaussDB commit后由桥接适配器抛DBCException；独立连接确认两表已经删除；两次不同选项重试均拒绝，commit总计一次 |

最后一项为确定性故障注入：数据库提交是真实的，丢失响应由适配器模拟，不是网络代理断包；不据此宣称所有网络故障时序已通过。界面仍使用整体错误及刷新提示，自动重试已禁用；主动重新发起操作时仍需以数据库当前状态为准。
