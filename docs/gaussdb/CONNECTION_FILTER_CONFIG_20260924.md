# 连接对象过滤配置验证

对应清单 3.12 的 schema 包含/排除和配置序列化、JSON 验证。调用实际 `FilterSerializer` 保存/读取，不是自制 JSON 替代生产实现。数据源容器为 mock，过滤器与 JSON 写入器为真实对象；无客户配置或凭据参与。

## 场景与测试方法

| 场景 | 输入、步骤与断言 |
| --- | --- |
| 大小写敏感/不敏感往返（2 项） | 名称包含双引号、描述含中文𠀀及换行；包含 Bank%/中文%，排除 Bank_private%。保存 JSON 再读取，逐字段比较；验证 Bank_public、bank_public、中文表及排除对象的匹配结果。 |
| 空用户过滤器 | 容器无任何映射；生产 serializeCustomUserFilters 必须返回 []，重新读取为空集合。 |
| 旧格式 | JSON 无 case-sensitive 字段；禁用状态保留，默认仍不区分大小写。 |
| 多范围隔离 | schema/db1 与 table/db2 两条过滤配置，读取后修改第一条不影响第二条。 |
| 无效输入（3 项） | 截断数组、错误顶层对象、数组中非对象元素，必须以 JsonParseException 拒绝。 |
| 父配置省略空字段 | 以具名 filters 字段保存空集合，父 JSON 仍只有其他字段，不额外产生数组或破坏结构。 |

## 缺陷与修复

首批运行 `run-aMCmNT` 中 5 项有 1 失败、1 错误：大小写设置未持久化；无映射时未输出任何 JSON 值，关闭 writer 报错。修复为读写 case-sensitive 字段，独立空文档输出 []，具名空字段继续省略；缓冲区明确按 UTF-8 解码。旧配置缺字段按 false 读取。

`run-9GkZIG` 首批修复后 5 项通过，全量已配置回归 1,338 项 / 1,314 通过 / 24 跳过 / 0 失败错误。后续无效输入及父配置对照需以最终运行记录为准。

## 边界

这不是完整连接导入/导出向导验收，也不证明凭据导出安全、磁盘加密、重启 UI 或 Windows 平台已经验证。没有修改用户配置文件；新增字段只保证当前修复版本的往返，旧版本是否读取该字段不作保证。GUI 安装包尚未同步本轮 registry 修复。
