# 批量删除不影响编辑器未提交事务：麒麟GUI验证

## 环境与前提

麒麟V10 x86_64隔离客户端、GaussDB507分布式测试库，模型与导航插件均为202609232338。与 `ATOMIC_DELETE_GUI_VALIDATION_20260924.md` 相同的三表夹具，在确认专用schema不存在后重建。不是客户业务数据。

## 实际操作及观察

1. 初次尝试在自动提交状态执行 `BEGIN` 再插入44，独立连接也读到44。该预检不满足“未提交”前提，不计通过；删除该测试行后改用工具栏事务模式。
2. 点击“切换到手动提交”，确认按钮提示变成“切换到自动提交”。在同一编辑器执行向 `batch_keep` 插入44，再查询按id排序的全部行：客户端成功返回2行；独立gsql仅返回33，确认44未提交。
3. 保持编辑器事务，打开导航树、刷新测试模式下的表列表，多选 `batch_first` 和 `batch_second`，右键删除，确认对话框仅列出这两表，不启用级联。
4. 删除完成：独立目录只剩 `batch_keep`，独立读取仍仅33。说明两张目标表已提交删除，而编辑器数据没有随之提交。
5. 回到原编辑器重复查询仍为2行；点击工具栏回滚，再查询变成1行；独立连接仍仅33。说明批量删除也没有把原编辑器事务回滚，44由用户显式回滚撤销。

结果：**通过上述成功批量删除场景的用户事务隔离验证**。SWTBot命令948–951为不满足前提的初次尝试，952–956建立并验证手动事务，957–962执行导航删除，963–964确认原事务仍有2行，965–967显式回滚后仅1行。客户端行数来自真实执行统计，不是模拟ResultSet；独立查询使用另一条gsql连接。

## 边界

未在本轮验证编辑器包含待保存DDL、批量操作失败时已有用户事务、UI中途取消、锁等待或其他连接隔离策略。本轮运行客户端尚未安装后续“未知提交结果防重放”补丁，不宣称该新补丁的GUI验收。

收尾：968–969恢复自动提交，按钮提示再次为“切换到手动提交”；显式删除残留对照表和专用schema，独立确认schema数量0。未删除业务数据。
