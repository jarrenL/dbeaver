# 查询历史持久化：事件生命周期验证

对应历史清单 3.11。`PersistentQueryHistory` 串行协调存储、事件身份、删除和保留期；尚未在产品注册监听器，不能作为完整 GUI 持久化交付。

## 已实现与验证

1. 同一元数据对象的重复回调使用同一 UUID，更新一条快照；保持当前进程对象身份，便于后续合并内存事件时去重。
2. 记录关闭时不检查 SQL、不生成文件；记录开启但过滤器拒绝时同样不落盘。
3. 删除先完成磁盘操作，再标记元数据删除；同一对象的延迟回调不能复活记录。
4. 重启恢复的记录仍可通过稳定 UUID 删除，未选记录保留，再次重开不会复活。
5. 文件不可写（测试将专用快照替换成目录）时抛错，内存记录不隐藏，也不打删除标记。
6. 容量及保留期清理同步移除可见持久化元数据，不只缩减文件。

上述六项使用生产生命周期层与映射器、真实临时文件；来源事件由生产元数据构造器重建，未模拟文件系统。run-7uTR8H 完整回归 1654 项、1631 通过、23 跳过、0 失败错误；六项新增测试全部通过。脱敏结果见 test-results-history-lifecycle-20260924.json。

补充：上一轮映射测试的最后一条损坏快照样例已在 run-3HCZCA 重跑通过，并通过编译产物核对确认使用格式 2；该轮为 1648/1625通过/23跳过/0失败错误。

## 接入约束与未验证项

- 后续将独立的持久化开关放入查询管理首选项，默认关闭，明确告知 SQL 内容会写入工作区文件；不能直接借用文本日志开关悄悄启用另一份存储。
- 记录调用应在事件分发后台线程；仍需完成浏览器合并、当前会话隔离、删除错误显示，以及首选项变更处理。
- 当前每条事件各自原子落盘，不宣称整批事件原子写入；没有性能或长时并发负载结论。
- 关闭流程须验证最后一批完成事件刷盘。当前 collector dispose 会清监听器后等待事件池，不能依赖该等待自动完成新增持久化监听器的最后一次写入。
- 当前序列测试覆盖“删除后延迟回调”，不替代真实多线程压力和 GUI 退出/重启验收。
