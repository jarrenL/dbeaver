# 查询历史持久化：事件生命周期验证

对应历史清单 3.11。`PersistentQueryHistory` 串行协调存储、事件身份、删除和保留期。运行时接入现已完成，见 [运行时接入](HISTORY_RUNTIME_INTEGRATION_20260924.md)；已执行的界面场景见 [GUI 验证](HISTORY_PERSISTENCE_GUI_20260924.md)。本页的组件测试不能单独作为完整 GUI 持久化交付证明。

## 已实现与验证

1. 同一元数据对象的重复回调使用同一 UUID，更新一条快照；保持当前进程对象身份，便于后续合并内存事件时去重。
2. 记录关闭时不检查 SQL、不生成文件；记录开启但过滤器拒绝时同样不落盘。
3. 删除先完成磁盘操作，再标记元数据删除；同一对象的延迟回调不能复活记录。
4. 重启恢复的记录仍可通过稳定 UUID 删除，未选记录保留，再次重开不会复活。
5. 文件不可写（测试将专用快照替换成目录）时抛错，内存记录不隐藏，也不打删除标记。
6. 容量及保留期清理同步移除可见持久化元数据，不只缩减文件。

上述六项使用生产生命周期层与映射器、真实临时文件；来源事件由生产元数据构造器重建，未模拟文件系统。run-7uTR8H 完整回归 1654 项、1631 通过、23 跳过、0 失败错误；六项新增测试全部通过。脱敏结果见 test-results-history-lifecycle-20260924.json。

补充：上一轮映射测试的最后一条损坏快照样例已在 run-3HCZCA 重跑通过，并通过编译产物核对确认使用格式 2；该轮为 1648/1625通过/23跳过/0失败错误。

## 接入约束与未验证项

### 多线程补验

`PersistentQueryHistoryTest` 新增两项，均使用生产生命周期对象、真实临时文件及有界线程池，不模拟锁或文件写入：

- `concurrentDeleteWaitsForRecordingAndDoesNotResurrectSelectedEvent`：记录线程在生产锁内通过 latch 暂停；启动删除请求后恢复记录。双方完成后再次发送被删事件，检查它仍被删除、未选对象未标记删除，重新打开文件仅恢复未选记录。
- `independentViewsCanDeleteSameSelectionWhileLateEventsArrive`：取得两份独立读取快照，两个线程同时删除相同选择，第三线程发送20批迟到/保留事件。等待全部任务结束后核对内存及重新读取文件都只剩未选记录。这里的“views”是读者快照，不是实际 SWT 窗口。

完整回归 `run-lSCNjD`：1668 项、1645 通过、23 跳过、0 失败/错误，见 `history-concurrent-results-20260924.json`。这两项验证有界线程交错，不声称穷尽线程调度或完成长时性能压测。

- 独立的持久化开关已接入查询管理首选项，默认关闭，明确告知 SQL 内容会写入工作区文件；它与文本日志开关分开。
- 记录调用接入事件分发线程，注册器关闭时还会保存已完成的待分发事件。浏览器合并、当前会话隔离、删除错误显示及首选项变更已有独立测试，具体范围见运行时接入报告。
- 当前每条事件各自原子落盘，不宣称整批事件原子写入；没有性能或长时并发负载结论。
- 关闭流程已补注册器主动保存快照及晚到通知终态保护，确定时序测试通过；不依赖 collector 清监听器后的等待完成持久化。不代表断电、强杀或精确 GUI 退出竞态通过。
- 序列测试与短时线程交错测试不能代替长期压力、跨进程文件并发或所有 GUI 多窗口操作。
