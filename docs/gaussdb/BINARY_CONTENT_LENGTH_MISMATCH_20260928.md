# 二进制内容长度不一致保护

日期：2026-09-28。历史场景映射：11.1 二进制类型、9.8 内容编辑、1.6 I/O 异常与资源释放。

## 缺陷与修复

`JDBCContentBytes.updateContents` 原先按存储声明长度调用 `readNBytes`，能够拒绝提前结束的流，但没有检查剩余数据。实际流超过声明长度时会静默接受截断值；声明长度为零时也会把非空流误存为空内容。

正式平台测试 `JDBCContentBytesReadTest` 新增三个长度场景：声明为 0、1、256，实际各多 1 字节。修复前，三个场景均因没有抛出预期异常而失败（联合 53 项中 50 通过、3 失败）。

修复在发布新值之前检查流末尾，发现额外字节时抛出 I/O 异常，经既有路径包装为数据库异常。原值保留，流正常关闭；同一值对象使用正确长度重试后完整保存，reset 恢复原值。补充第四个场景：全部 257 字节读取成功，但末尾探测抛 I/O 异常，验证原始 cause、关闭、原值保留和重试。

## 边界与剩余验证

- 生产值对象、真实内存流及故障注入流；存储元数据为测试替身。
- 这是长度契约不一致的保护，不是任意外部文件竞态的原子快照保证；同长度内容变化、探测后的文件变化未据此覆盖。
