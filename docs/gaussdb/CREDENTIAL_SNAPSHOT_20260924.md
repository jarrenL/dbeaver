# 凭据保存选项与属性隔离验证

对应清单 3.12/3.13/10.3 的连接配置及凭据处理边界。新增 `SecureCredentialsHistoricalTest`，调用生产 `SecureCredentials` 和 `DataSourceParser.saveCredentialsToMap`。所有密码、token 都是测试常量，不使用真实连接凭据；没有输出用户配置或密码日志。

## 测试方法

| 场景 | 步骤及预期 |
| --- | --- |
| 数据源保存选项（2） | 分别设置 savePassword=false/true，构造生产凭据并调用生产 map 序列化；用户名保留，password 键随选项省略/存在，原运行时密码不被清除。 |
| 隧道保存选项（2） | 网络处理器分别启用/关闭保存密码，同样验证序列化字段。 |
| 认证配置保存选项（2） | 认证 profile 分别启用/关闭保存密码，同样检查字段和运行时密码保留。 |
| 数据源属性隔离 | 构造凭据后修改其中 token，原连接属性不变；再修改原配置，新属性不进入已构造凭据。 |
| 只读 profile 属性 | 使用不可修改 Map 构造，给凭据添加属性成功且不改动原 profile。 |
| 自身集合与只读视图替换（2） | setProperties 输入自身属性或其不可修改视图，不丢内容；传入空集合后序列化为空。最初输入集合的后续修改也不影响凭据。 |
| 空凭据 | null/空用户名及密码不产生字段；随后添加扩展属性可序列化。 |

## 已发现问题

`run-0aLfX9` 首批 9 项中 5 通过、3 失败、1 错误：属性集合共享造成原配置被修改，只读集合添加抛异常，自身集合或视图重新赋值丢失内容。修复为构造和替换时复制 Map；不改变 getProperties 可修改的现有约定。

`run-mq2qtn` 首批修复后 9 项全通过。追加认证 profile 保存选项两项后，`run-tBLu1k` 复现 false 时仍输出 password。检查生产 `DataSourceSerializerModern.saveAuthProfiles` 的调用确认该构造用于凭据序列化；将 profile 构造逻辑与数据源、隧道保持一致，仅 savePassword=true 时保留主密码。不清除运行时原 profile 密码，不擅自删除认证扩展属性。

## 边界

这是生产凭据模型及 map 序列化测试，不代表完整导入导出向导、实际安全存储加密、文件权限或操作系统钥匙串验证。自定义认证属性与 user/password 保留键冲突、既有安全存储记录的删除/更新、全部认证模型的秘密字段策略仍需进一步审计。不能据此宣称“任何秘密都不会导出”。

尤其是 `DBAAuthProfile.persistSecrets` 属于另外的安全存储路径，本轮不以 map 测试替代它的验证。GUI 安装包还未同步本轮 registry 变更。
