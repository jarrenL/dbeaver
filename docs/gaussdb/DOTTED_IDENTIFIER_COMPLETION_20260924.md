# 带点号的引号标识符补全

对应历史清单 6（解析工具）、8（名称/别名解析）、9.5（对象补全）。此项与先前普通引号名称测试的环境校正不同：在已安装真实 SQL 分区器的测试文档中复现了生产代码缺陷。

## 场景与断言

模型目录为 `Database1` → `a.schema` → `a.table`。输入 `SELECT * FROM Database1."a.schema"."a.ta`，在表名前缀末尾触发传统补全。

- 有闭合引号：必须提供 `"a.table" t`；按真实替换偏移和长度应用后，不残留旧前缀或多余引号。
- 无闭合引号：在文档末尾仍能识别完整限定名称，返回同一候选。
- 后接 `WHERE 1 = 1`：仅替换当前名称，保留后续 SQL。
- 底层名称拆分：双引号、反引号和方括号的未闭合组件均保留内部点号，分别验证保留和去除引号两种输出。

测试入口为 `SQLCompletionAnalyzerTest.testQuotedDottedTableCompletionReplacement` 和 `SQLUtilsTest.splitIncompleteQuotedIdentifierPreservesInternalSeparator`。同时回归原有数据库、schema、表、列和别名补全测试。

## 修复点

1. `SQLUtils.splitFullIdentifier` 不再拆开未闭合引号内部的点号。
2. 候选过滤不再将已加引号的表名前缀误作层级路径。
3. 替换范围计算屏蔽引号内部的分隔符，并消费当前组件的闭合引号，而不是判断整个限定名称是否加引号。
4. 文档末尾的空默认分区不再掩盖前一个字符所属的未闭合引号分区。
