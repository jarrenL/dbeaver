# 二进制内存缓存补充回归

日期：2026-09-28。场景映射：1.6 流与资源、9.8 数据编辑、11.1 二进制及中文内容。

生产调用链：`ContentEditorInput.updateContentFromFile` 的缓存内容分支调用 `BytesContentStorage.createFromStream`。本轮直接测试该缓存工厂，不等同于验证完整编辑器分支或数据库提交。

## 新增 10 个场景

- 0、1、257、65537 字节，以每次最多 7 字节读取，验证完整内容、实际长度、多次打开缓存流及源流关闭。
- 长度提示为 -1、0、500 时，真实中文/引号/反斜杠/换行内容仍全部读取，实际长度、UTF-8 编码及 Reader 解码正确。
- 读取 I/O 异常原样传播，源流关闭。
- 声明长度超过 int 上限时，读取前拒绝且不访问输入流，不尝试大内存分配。
- 释放原存储后克隆仍可读取，编码保留。此项不宣称可变字节数组深拷贝隔离。

缓存工厂将长度作为提示，并按实际全部内容构建缓存；与严格检查存储契约的 JDBCContentBytes 不同，未发现此前的静默截断问题。本轮没有修改生产代码。

## 测试修正与结果

首次 5 项失败是测试错误假设输入流归调用者关闭。核查 `IOUtils.copyStream` 注释与 finally 实现后，确认工厂通过该工具关闭流；修正测试断言，不计作产品缺陷。初始日志 `/tmp/cache-storage-20260928.log` 保留。

- 共享组件：731/731，0 跳过，退出 0，日志 `/tmp/cache-storage-final-20260928.log`。
- 平台真实 OSGi：15 类、299/299，0 失败/错误/跳过，退出 0，逐类门控通过；日志 `/tmp/cache-storage-osgi-20260928.log`，报告 `/tmp/gauss-existing-osgi-6rCoeD/reports`。
- 结果校验器：7/7；新类加入必需类检查，不与客户端测试计数相加。

正式测试位于 `org.jkiss.dbeaver.test.platform` 的 `BytesContentStorageTest`。专项运行器显式编译生产工厂与测试；编译输出 `/tmp/shared-focused-2dNAib`。两个测试批次重叠，不累计场景数。

尚未覆盖真实磁盘并发变化、内存耗尽、GUI、数据库写入或完整产品构建；本报告不能证明全部缓存/大对象需求完成。
