# 客户端异常封装与诊断保留验证

对应历史清单1.2、1.6和6.3的异常提取与错误处理。映射至DBeaver共享生产类DBDatabaseException、DBCException、DBSQLException，不照搬TPDSS异常类型。

## 场景及结果

新增DatabaseExceptionContractTest，10项组件测试全部通过、0跳过、0失败；日志`/tmp/exception-contracts-20260928.log`。本轮未发现需要修改的生产代码。

1. 六类SQLSTATE（唯一键23505、外键23503、权限42501、语法42601、取消57014、连接08006）：构造原始SQLException后由生产类封装，验证错误码、状态、中文/补充平面字符消息保留；原cause、nextException和suppressed身份保留。此处是封装契约，不是数据库真的触发六种错误或错误分类器测试。
2. 两项缺失消息与SQLSTATE：厂商错误码0和1234，封装不引入二次异常；非零码保留备用错误文字。
3. 嵌套执行异常：自定义消息不被覆盖，执行上下文和数据源在包装后保留；无显式消息的外层包装仍可获取内层数据源。
4. SQL异常上下文：getSqlQuery精确保留原SQL，原cause/上下文/数据源不丢失；包装器不自行将SQL追加至错误消息。此项不等于完整日志脱敏审计，服务端消息本身仍可能包含SQL。

## 复跑与限制

测试仓`scripts/run-exception-focused.mjs`直接编译上述三个当前生产类及共享平台测试类，使用既有只读依赖。上下文与数据源使用Mockito，不执行SQL、不访问网络、不写业务数据；不是完整OSGi启动、真实取消恢复、GUI错误弹窗或供应商驱动协议验收。真实数据库异常、任务取消与关闭路径分别保留其他专项证据，不混计本轮10项。
