# 查询历史持久化：事件映射

对应历史清单 3.11。本阶段在快照存储上增加 `QueryHistoryEventMapper`，尚未注册运行时监听器或替换默认历史浏览器，GUI 跨重启验收仍未完成。

## 数据保真与隔离

- 保存完成查询的 SQL 原文、项目 ID/名称、连接 ID/名称、驱动 ID、执行上下文名称、schema/catalog、用途、开始/结束与获取时间、返回行数、更新行数及错误信息。
- 返回行数与 DML 更新行数分别保存；旧快照格式不包含这些字段，格式从内部开发版本 1 升至 2。版本 1 明确拒绝，不将缺失字段的默认 0 当成真实结果。该功能尚未作为交付版持久化功能启用。
- 恢复为关闭的元数据对象，JDBC statement 引用、事务和保存点为空。历史会话使用 `history:<UUID>` 标记，不复用当前应用会话 ID。
- 未结束、仍在取数、已删除、连接禁止日志、空 SQL 和非查询事件不生成快照。它只检查已有元数据状态；用户记录开关、敏感语句过滤及事件生命周期完整接入仍需在监听层落实，不能单凭这些检查宣称全部敏感数据已保护。
- 保留项目名称而不是用 ID 冒充名称，供历史页面重新查找连接使用。连接已删除或重命名后的 UI 导航还需单独验证。

## 验证方式

新增 6 项测试：生产事件映射、真实快照文件重开及生产元数据重建；源查询执行元数据模拟。覆盖 SELECT 中文多行与 42 行、执行加获取耗时、DML 更新 7 行与错误、活动/取数/删除排除、禁止日志与空 SQL、非查询事件、连接名缺失回退。额外断言项目名称和上下文名称。

第一轮 run-3e8scD：1648 项、1625 通过、23 跳过、0 失败错误。补项目名称与上下文名称后 run-DpTNq6 完整回归同样为 1648/1625通过/23跳过/0失败错误。安全报告为 test-results-history-event-mapping-20260924.json。测试不是 JDBC 执行或 GUI 持久化验收。
