# 凭据保留字段冲突验证

## 范围

对应历史清单连接配置、安全凭据、不保存密码及配置持久化。直接调用生产 SecureCredentials 和 DataSourceParser.saveCredentialsToMap；测试仅使用虚构字段，不读取或输出真实凭据。

## 问题与修复

旧序列化先写主用户名/密码，再 putAll 认证扩展属性。当扩展属性含 `user` 或 `password` 时，可以覆盖主用户名、主密码，或在主密码因保存开关为 false 而省略时重新加入 password。

修复让这两个保留字段只能来自主凭据。扩展属性中的同名键不写入该扁平记录；token 等其他属性仍保留，且不修改来源属性集合。依赖同名扩展键传递主凭据的扩展应使用主字段，不能利用合并顺序覆盖保存选项。

## 五项新增测试

- 数据源保存密码开/关两种情况下：主用户名始终保留，主密码只在允许时保存；扩展 token 保留，来源 Map 不变。
- 认证 profile 保存密码开/关两种情况下验证同样规则。
- 主字段为空时，不从扩展属性重新引入 user/password，只保留其他字段。

修复前 `run-Ok3AmB` 五项均失败。失败运行不用于声称其他模块已重新通过。

## 边界

修复后 `run-E7bLUX` 五项新增用例全部通过；整套新鲜结果 1435 项、1411 通过、24 跳过、0 失败/错误。临时授权角色已删除。[脱敏逐例报告](test-results-20260924-credential-reserved.json)。

本轮验证扁平序列化记录，不代表所有安全存储实现、认证插件自定义秘密字段、磁盘加密和 GUI 开关都已验收。没有宣称所有扩展 token 受“保存主密码”开关控制；该开关在本轮仅控制保留的主密码字段。
