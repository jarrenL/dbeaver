# 内容保存取消保护

日期：2026-09-28。对应历史场景 9.8 数据编辑、1.6 执行异常、9.1 导入取消及重试。

## 发现及修复

保存和导入是不同阶段，此前导入取消测试不能证明保存取消安全。

新增平台测试三项：开始保存前取消（存储更新、设为 NULL 两种）、读完内容后取消。此前 JDBCContentBytes 不检查取消，仍会读取或发布新值。修复在接触存储前及完整读取后、发布前检查监视器，取消时报数据库异常，不覆盖旧值。后续使用同一对象重试及 reset 已验证。

新增编辑器测试两项：文本与二进制导入后，使用已取消监视器保存。文本原先仍更新控制器；二进制即使下层拒绝，入口也仍调用更新方法。修复 ContentEditorInput 保存入口，取消时不调用发布方法、不清除待保存状态；解除取消后再次保存，内容与源文件一致。

## 失败与通过证据

- 平台首轮存在未配置流导致的夹具空指针，未作为产品缺陷证据。配置合法流重跑后，三项均明确因未抛预期异常而失败：`/tmp/content-save-cancel-red-valid-20260928.log`。
- 加入取消检查后，原有纯组件测试的 VoidProgressMonitor 访问平台服务产生空指针。改用明确返回未取消的测试监视器，未修改生产平台行为。
- 编辑器有效红测两项：`/tmp/content-save-input-red-valid-20260928.log`。修复后全部通过。

## 尚未证明

这是合作式取消，在入口及读取完成后阻止发布，不强制中断阻塞 I/O，不保证消除取消检查与赋值之间的全部竞态。取消作为异常返回，真实进度窗口的提示与关闭行为尚待 GUI 验收。二进制值对象及文本入口已覆盖，不推及全部 Blob/Clob 实现。

尚未部署 Linux 客户端、连接真库重验或构建完整安装包。目标继续进行中，不将本报告作为全量验收结论。
