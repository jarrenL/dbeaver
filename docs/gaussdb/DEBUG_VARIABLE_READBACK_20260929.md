# 调试变量赋值：绑定、回读失败与独立刷新

## 对应需求

原始需求“查看和手动修改变量”，历史清单的设置变量值与执行异常。本轮新增8项生产GaussDBDebugSession测试；既有拒绝值、无返回行、SQL异常、SQL NULL、常量和非当前帧只读测试仍参与回归。

## 新增场景及测试方法

| 场景 | 测试方法与断言 |
| --- | --- |
| 空文本、算术表达式、中文/引号/分号文本、NULL文本（4项） | 使用固定的set_var(?, ?)语句，检查名称和值分别绑定，未拼接SQL；缓存采用info_locals返回的服务端表示，不采用输入表达式 |
| 回读无匹配行（1项） | set_var已返回true，info_locals无行；明确抛错，不宣称赋值确认，不把输入表达式存入缓存 |
| 回读查询、结果集关闭、语句关闭失败（3项） | 分别注入SQLException，检查原始原因传播、原缓存保留，set_var只执行一次 |
| 上述4种回读失败后的独立刷新 | 给新的info_locals查询准备结果8，读取成功且不再次调用set_var，避免重放可能有副作用的x + 1 |

生产转换和控制流程实际执行，JDBC应答由Mockito提供。特别是空文本及特殊字符场景仅证明参数绑定路径，**不证明服务端接受全部这些表达式或变量类型**。

GaussDBDebugSessionTest **63/63通过、零跳过**。73模块中五个测试模块合计**2624项：2450通过、173跳过、0失败、1错误**。唯一错误仍为RestTest本地网络权限拒绝，独立门禁拒绝整体通过。诊断命令允许错误后继续收集后续测试结果，不代表忽略验收错误；跳过不算通过。

发生回读失败时旧缓存值不是服务端当前值的证明，服务端可能已经完成赋值；必须处理错误并独立刷新。测试不证明真实数据库中的赋值结果、变量窗格刷新时机或网络中断端到端表现，也不将模拟执行次数等同于真实网络语义。
