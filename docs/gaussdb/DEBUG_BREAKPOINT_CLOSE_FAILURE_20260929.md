# 已确认断点与资源关闭异常

## 覆盖场景

对应历史清单“断点设置/显示/移除”和JDBC资源关闭异常。新增4项：ResultSet或PreparedStatement关闭失败，各覆盖初始启用和初始禁用两种请求。

测试让真实GaussDBDebugSession读取服务端返回的编号0，随后由Mockito注入关闭SQLException，检查：

- 异常仍向调用者传播，原始原因不丢失。
- 注册列表保留同一断点及编号0。
- 若关闭结果集时失败，后续禁用尚未发送，状态必须是已启用。
- 若关闭添加语句时失败，按此前实际完成的禁用命令保留相应状态。
- 随后的显式删除确实绑定编号0执行，并清除注册列表，不因先前异常而找不到断点。

## 发现与修改

红测2项失败：ResultSet关闭异常时，客户端列表为空。原因是注册记录原来在结果集try-with-resources结束之后才保存。语句关闭异常的另外2项原本通过。

调整为在读取并校验有效编号后立即保存已确认的注册和启用状态，再关闭结果集。仍保留原始异常报告；不会在关闭失败后继续发送禁用命令，也不会伪造尚未返回的服务端编号。

日志：`/tmp/debug-breakpoint-close-red-20260929.log`、`/tmp/debug-breakpoint-close-green-20260929.log`。逐项结果见[测试证据](evidence/DEBUG_BREAKPOINT_CLOSE_REACTOR_20260929.json)。

修复后会话类**50/50通过，零跳过**。73模块中五个测试模块合计**2611项：2437通过、173跳过、0失败、1错误**。唯一错误仍为RestTest本地网络权限拒绝。诊断运行允许错误后继续收集后续测试，独立验收门禁仍拒绝整体通过；跳过不算通过。

## 验证边界

本轮是生产方法级测试，服务器结果和关闭异常均通过JDBC替身注入；不能代替真实驱动网络故障、断点窗格恢复、GUI错误提示或服务端响应丢失验收。未读取到编号的远端未知结果没有在本轮解决。辅助审核因本地日志目录权限不足未初始化成功，没有审核结论。
