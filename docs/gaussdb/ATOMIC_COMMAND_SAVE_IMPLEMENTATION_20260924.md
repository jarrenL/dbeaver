# 整批命令原子保存：模型层实现阶段

新增显式选项 `DBECommandContext.OPTION_ATOMIC_TRANSACTION`。它与原有仅控制模型反映时机的 `atomic` 构造参数不同；未指定选项时原路径不变。

新路径要求调用者拥有隔离执行上下文，且连接已建立、支持事务和事务性DDL、当前自动提交。已有手工事务直接拒绝，不能提交用户未保存工作。执行前验证全部命令，拒绝要求避开事务的命令、已执行命令以及目前未适配的可选/最终动作类型。执行中检查取消，全部成功只commit一次，失败rollback且不更新模型；rollback失败时不恢复自动提交，以免提交部分工作。commit成功后先移除待执行命令，防止后续关闭/自动提交恢复错误导致重放。

当前对照测试调用实际模型保存路径：旧路径第一命令已commit后第二条失败；新路径相同第二条失败时无commit、有rollback，两个对象模型均未更新。

**仍未完成**：导航树必须聚合命令并为该选项创建真正隔离连接；不能直接在共享连接启用。成功/取消/rollback失败/commit响应不确定等边界及真实数据库调用新路径尚需继续补验。现有GUI批量删除仍走旧路径，原子回滚仍未闭环。当前实现只接受NORMAL/COMMENT动作，其他类型在执行前拒绝，不默默降级为非原子操作。

## 真实数据库事务桥接验证

`GaussDBHistoricalJdbcLiveTest.atomicCommandSaveControlsRealDatabaseTransaction` 直接调用生产代码 `AbstractCommandContext.saveChanges` 的原子选项。模型、会话和对象管理器适配器使用模拟对象，但事务切换、执行DDL、提交和回滚均转发到独占的真实 GaussDB JDBC 连接；不是手工事务脚本替代生产保存逻辑。每次使用随机独立 schema，结束后清理测试对象。
