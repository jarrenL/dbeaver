# CSV 换行替换文本的字面量边界

对应清单9.1导出格式、6.3字符串处理。新增 `GaussDBCSVReplacementTest`，调用生产CSV导出器，并用CSV导入器使用的CSVReader解析输出；绑定/会话是测试替身，不使用数据库或图形界面。

## 发现

换行替换选项是用户文本，不是正则替换程序。原实现直接把配置传入 Matcher.replaceAll，导致 `$`、`$1`、`${line}`、反斜杠、带反斜杠路径、含引号/美元符号/逗号的文本发生异常或静默丢字符。7项场景中6项实际失败；中文与扩展字符标记原本通过。

## 修复与验证

DataExporterCSV 通过 Matcher.quoteReplacement 转义替换程序的元字符；之前配置阶段对 `\\t`、`\\n`、`\\r` 的展开逻辑不改变。共享CSV导出器受影响，不仅是GaussDB。

新增10项专项：

- 7种字面标记：同一字段包含LF、CRLF、引号、逗号和扩展汉字，精确核对序列化文本，CSVReader重新解析为两列、仅一条记录；不含换行的第二列 `$1` 与反斜杠原文不变。
- 3种控制字符配置：`\\t`、`\\n`、`\\r\\n` 仍按配置展开，输出严格相等。

红测 `/tmp/csv-focused-red.log` 为7项、1通过、6失败。修复后 `/tmp/csv-focused-green.log` 为10项、10通过、0跳过、0失败，临时编译目录 `/tmp/csv-focused-altNaU`。

专项脚本：独立测试仓 `scripts/run-csv-focused.mjs`，直接编译当前生产导出器与新测试类，使用已有本机依赖。与XLSX专项相同，JDK25/Java21目标，JUnit Console 1.13.1；不需要写Maven缓存，但不是完整Tycho/OSGi测试。该脚本仅适合当前已有依赖的开发环境。

## 未覆盖范围

本轮没有重跑原平台CSV测试整类，没有GUI设置和导出向导、真实JDBC取值、字符集文件编码、SQL NULL选项或全部导入流程的新验收证据。CSVReader复读不能替代其他软件的兼容性检查；控制字符配置3项只核对输出，不宣称任意换行都无损往返。完整回归、安装包及真库仍需恢复运行环境后执行。
