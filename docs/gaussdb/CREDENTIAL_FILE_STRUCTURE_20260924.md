# 凭据加密器与损坏文件校验

## 范围及方法

对应历史清单 3.13（加解密）及 10.3（配置磁盘读写）。使用生产 `DefaultValueEncryptor`、JUnit 临时目录和虚构密钥/内容，不读取用户现有凭据。文件由测试直接读写，尚不等同于完整连接配置保存、重启恢复或系统钥匙串验收。

新增 15 项执行用例：

| 场景 | 数量 | 操作与断言 |
| --- | ---: | --- |
| 加密文件往返 | 5 | 空串、普通文本、中文/扩展汉字/引号/反斜杠/换行/NUL、16 字节边界及超过边界；加密后写临时文件，以新实例解密逐字节比对，输入及原文件不变 |
| 随机初始化向量 | 1 | 同实例重复加密相同内容，IV 不同，两份都可恢复 |
| 截断文件 | 8 | 0/1/15/16/17/31/33/47 字节文件必须报 DBException，失败不修改原文件 |
| 损坏填充与恢复 | 1 | 通过 CBC 链改变末尾填充字节，解密失败；同实例随后仍能解密原有效数据 |

## 复现和修复

`run-jvBnfx` 中 0/1/15/16 字节四种截断输入未被拒绝。流式解密返回空内容，会掩盖凭据文件已损坏的事实。

解密前增加结构校验：数据必须包括完整 IV 和至少一个填充后的密文块，且总长度必须为块大小的整数倍。未更换算法、密钥处理和文件格式；有效空内容仍可往返。错误信息不含凭据原文。

## 安全与覆盖边界

- 此路径为 AES/CBC/PKCS5Padding，并非带认证加密。长度及填充检查不能保证识别所有篡改，不能据此宣称完整防篡改能力。
- `LocalSecretController` 是另一条基于首选项的路径，源码明确不负责加密；不能把本轮结果套用到它上面。
- 本轮未验证完整配置管理器的文件替换原子性、权限、系统钥匙串、并发访问或 GUI 保存开关。
- 全部测试数据均为虚构内容，测试临时目录由 JUnit 管理。
