# 执行计划文件格式回归

## 对应历史场景

对应清单7.1/7.2计划节点及树格式、字段映射，以及文件导入异常处理。使用 PostgreSQL/GaussDB 共用的生产 `PostgreQueryPlaner` 反序列化/序列化实现；模拟数据源只提供驱动签名，不建立JDBC连接。

## 用例

`PostgreSavedPlanTest` 共12次执行：

| 场景 | 数量 | 断言 |
|---|---:|---|
| 序列化往返 | 1 | 中文SQL、Sort→Function Scan层级、直接父节点、实际5行、耗时0.022、成本74.83不丢失；数据源仅读取签名，无其他交互 |
| 损坏/无结构输入 | 6 | 空串、null、数组、截断JSON、空对象、null根节点以异常返回；同一个解析器随后能读正常文件 |
| 不兼容版本 | 3 | 0、2、999拒绝读取 |
| 缺失版本 | 1 | 拒绝读取 |
| 不同驱动签名 | 1 | 拒绝读取 |

## 发现和修复

原实现没有读取 `version`，因此不兼容版本及缺失版本共4项失败（run-YP9SJ7）；其余8项通过。更早一次运行是测试代码类型编译问题，不计作产品失败。

生产修复仅在 PostgreSQL 计划读取入口校验当前格式版本1；不改变文件写入格式，不替代其他数据库驱动的版本策略。不兼容文件向既有上层错误处理返回异常，而不是按当前格式猜测解析。

## 证据边界

修复后完整回归 run-dqqC84：1505项，1481通过、24跳过、0失败/错误；新增12项全部通过。结果见 `test-results-saved-plan-20260924.json`。本轮构建跳过Checkstyle/格式检查，不宣称这些检查通过。

这些测试不替代文件选择器/错误弹窗GUI验收，不覆盖所有计划节点或超大文件/恶意深层嵌套。既有GUI保存加载验证见 [麒麟执行计划界面验证](PLAN_GUI_ACCEPTANCE_20260924.md)。新增版本检查尚未安装到GUI隔离客户端。
