# Linux SQL执行中断连与恢复

关联历史清单1.1、1.5、1.6、9.7：连接失败、执行异常、取消及后续连接可用性。环境为麒麟V10 x86_64测试副本DBeaver 26.1.5、GaussDB 507分布式测试库，普通测试账号。仅执行只读SELECT，不修改业务对象。

## 可重复操作

1. 在专用SQL编辑器执行 `SELECT pg_sleep(120) /* dbv_gui_inflight_disconnect_20260924 */;`。
2. 从独立管理员连接查询pg_stat_activity，按测试库、测试账号、active、唯一SQL注释筛选，确认application_name属于目标SQL编辑器。不要只按用户名终止全部连接。
3. 对已核对的会话按pid、库、账号、完整application_name、active和唯一标记联合筛选执行pg_terminate_backend。该操作会终止所选会话，必须只针对无写入、无业务事务的专用测试查询。
4. 观察客户端、服务端会话和重连日志。如果查询被重试，不把仍在执行误判为取消失败，也不等待120秒自然结束冒充即时恢复。
5. 点击当前结果面板Cancel，独立检查带唯一标记的active查询计数归零；检查执行日志显示取消。
6. 同一编辑器执行 `SELECT '恢复验证中文' AS probe, 42 AS value;`，切换结果面板“文本”，逐值检查中文和42，而不是只看成功提示。

## 本次结果

- 1067–1069：执行唯一标记等待查询；独立确认SQLEditor <Script-2.sql>、active、pid281470032525632。
- 对上述完整筛选条件终止会话，返回t。
- 1070–1071：没有错误弹窗；日志01:50:42记录Invalidate datasource。服务端重新出现相同标记的active查询，backend_start=01:50:42.216265、query_start=01:50:42.257295。GaussDB复用了pid，不能仅凭pid相同认定没有重连。实际行为为重连后重试只读查询，而非立即向用户报错。
- 1072点击可见Cancel；1073执行日志显示“Statements of the current request are canceled”；独立活动查询计数为0。查询在重试后约58秒被测试操作取消，早于120秒自然完成，不能把这58秒解释为取消按钮响应耗时。
- 1074–1075：同一编辑器中文查询成功，1行。
- 1076：结果文本控件可见内容为 `probe |value| ... 恢复验证中文|   42|`，实际值通过。

本轮运行中连接终止后的只读重试、取消和后续编辑器查询恢复通过。无需对象清理，服务端没有残留带测试标记的活动等待查询。

## 边界

不代表写操作、存储过程或提交结果不确定时可以安全重试；不能以SELECT场景为DML恰好执行一次背书。本轮未做网络分区、主备切换或底层集群恢复，也未证明所有SQL错误都会弹窗。与空闲元数据连接刷新恢复为不同场景，分别记账。
